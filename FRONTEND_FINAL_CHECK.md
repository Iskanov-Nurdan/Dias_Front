## 1. Рецепты

- **Один select в составе** (префиксы «Сырьё: …», «Химия: …»): **OK** (`RecipesPage.jsx`, `RecipeCompositionModal`, `unifiedOptions`).
- **Нет переключателя raw/chem** в UI состава: **OK** (тип берётся из выбранного `raw:` / `chem:`).

## 2. Производство (ProductionBatch)

- **Форма: профиль, рецепт, линия, pieces, length_per_piece**: **OK** (`ProductionBatchModal.jsx`).
- **Нет поля total_meters**: **OK**.
- **Нет ручного ввода себестоимости**: **OK**.
- **Рецепт фильтруется по профилю**: **OK** (`recipesForProfile`).

## 3. RecipeRun (экран химии / полуфабрикат)

## 4. ОТК

## 8. Realtime

# Найденные проблемы

1. В `PAGE_LABELS` пункт меню химии назывался «Замесы по рецепту» — противоречило требованию терминологии и цепочке ProductionBatch.
2. В комментариях `otkApi.js` и `recipeRelease.js` оставались формулировки про «замес».
3. Подписка на WS для ОТК не учитывала ресурс `recipe_run` — при событиях только по нему список мог не обновляться.
4. Склад подписывался только на `warehouse_batch` — при событиях по `batch` / `production_batch` после ОТК список мог не обновляться.
5. На странице химии кнопки и модалка «Произвести» визуально пересекались с понятием «производство = партия профиля» (риск путаницы с ProductionBatch).
