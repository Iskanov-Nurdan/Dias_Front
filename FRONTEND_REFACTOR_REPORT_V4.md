## Химия (`ChemistryPage`)

- Убран дубль `h1` с шапкой.
- Модалка «Проверка остатков»: вместо сырого JSON / `<pre>` — таблица с колонками для клиента (компонент, тип, норма, остаток, нужно на выпуск, достаточно / нет); данные нормализуются в `recipeAvailabilityRows.js`.

## Профили (`PlasticProfilesPage`)
- Убран внутренний `h1`.
- «Создать рецепт» убрано из отдельной primary-кнопки в тулбаре — доступ через меню строки (`ActionMenu`).

## Линии / открытие смены (`LinesPage`)
- Сокращены подсказки; убраны упоминания технического «ProductionBatch» в тексте для оператора.
- В форме открытия смены в payload уходит одно поле комментария (`comment`), без дублирующего `notes` в том же запросе.

## Партия производства

- `ProductionBatchDetailModal`: заголовок «Партия №…», короче подсказка; штуки при редактировании — `IntegerInput` и целочисленный разбор при сохранении.

## ОТК (`OTKPage`)
- Поля принято/брак — `IntegerInput`, логика отправки ориентирована на целые значения.
- Убраны лишние подсказки/атрибуты формы; убран неиспользуемый импорт форматирования числа для ввода.

## Склад — упаковка из ОТК (`PackFromOtkModal`)
- «Упаковок» и «Штук в каждой» — `IntegerInput` с `min={1}`.

## Продажа (`SalesPage`)
- Где нужны штуки, упаковки и переопределение штук в упаковке — `IntegerInput` (в т.ч. `min={0}` там, где допустим ноль по сценарию).

## Клиенты (`ClientsPage`)
- Убран верхний блок длинного описания страницы (`ds-page-top`).

## Аналитика (`AnalyticsPage`)

- Кнопка «Сброс» сбрасывает расширенные фильтры.
- Подписи на карточках и блоке трендов сокращены (меньше «технички» и длинных фраз).

## Навигация

# Что исправлено в decimal / input logic

| Компонент / место | Было / риск | Стало |
|-------------------|------------|--------|
| `DecimalInput` | При фокусе значение переписывалось форматированием — терялись ведущие нули и промежуточный ввод (`0.80`, `0.001`). | При фокусе показывается сырая строка; форматирование применяется в размытии (`blur`) с проверкой min/max и пустого ввода. |
| Штуки, упаковки, ОТК, партии, продажи | Риск дробного ввода или `Math` там, где нужны целые. | Введён `IntegerInput`: только цифры, на blur — `parseInt` и clamp по `min`/`max`. |
| Дробные поля (кг, метры, нормы и т.д.) | Остаются на `DecimalInput` с исправленной логикой фокуса. | Сохранение точности при наборе до подтверждения поля. |

# Что исправлено в recipe availability

- Ответ API разбирается в `buildRecipeAvailabilityRows`: поддерживаются разные варианты массивов (`items`, `results`, `components`, и т.д.).
- В UI: таблица с понятными колонками (компонент, тип, норма на метр с единицей по умолчанию «кг/м» при отсутствии своей, остаток, достаточность да/нет/—).
- Сообщения об ошибке или текст с бэка выводятся отдельно, не как сырой объект.

- Вместо полей «введите id» — `Select` с названиями сущностей.
- Загрузка опций одним `useEffect` при монтировании (линии, клиенты, профили, рецепты, партии).
- Компактнее текст подсказок у карточек и в секции трендов.
- Период «с / по» и статус — без смены общей схемы, в одном блоке расширенных фильтров.

# Что проверить вручную

1. Рецепты → открыть рецепт → «Проверка остатков» — таблица заполняется на вашем ответе API; при пустом ответе — адекватное пустое состояние / сообщение.
2. Профили → одна primary в тулбаре; «Создать рецепт» только из меню строки.
3. Химия → один основной «Выпуск» в нужном месте; вкладка остатков без лишнего дубля.
4. Линия → открытие смены: комментарий уходит, смена открывается.
5. Партия: создать и отредактировать штуки (границы min).
6. ОТК: ввод принято/брак целыми, сохранение.
7. Склад → упаковка из ОТК: целые упаковки и штуки в упаковке, итог штук.
8. Продажа: количества и упаковки, сценарии с нулём где разрешён `min={0}`.
9. Аналитика: фильтры меняют запрос; сброс очищает расширенные фильтры; графики грузятся без ошибок.
10. Дробные поля по приложению: ввод `0,80` / `0.001` / пусто / `0` — без «скачка» при клике в поле.
11. Моя смена: одна кнопка жалобы там, где задумано; заголовок не дублируется.
