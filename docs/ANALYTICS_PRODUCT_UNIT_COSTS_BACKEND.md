# Промпт для бэкенда: «Себестоимость товара» в аналитике

Фронт уже готов. Нужен один эндпоинт-справочник + уточнение `summary` (см. ниже).

---

## Бизнес-логика (как на UI)

| Блок | Поведение |
|------|-----------|
| **Всего расходов** | только `purchase_total` (приход сырья за период) |
| **Маржа** | `revenue_total` − `purchase_total` |
| **Строка «Себестоимость товара»** | Не сумма за период, а справочник: все профили/товары и **текущая** себестоимость за 1 шт |
| **Модалка** | Таблица: название профиля \| себестоимость за шт |

`GET analytics/sales-cost-details/` для этой строки **не используется** (остаётся только для старой детализации прибыли, если нужна).

---

## Новый эндпоинт (обязательно)

### `GET /api/analytics/product-unit-costs/`

**Права:** `access_key = analytics` (как у остальной аналитики).

**Query (опционально, можно игнорировать):**  
`year`, `month`, `day`, `date_from`, `date_to`, `line_id`, `client_id` — фронт передаёт те же параметры, что у `summary/`, но данные **не зависят от периода** (актуальный справочник на момент запроса).

**Response `200`:**

```json
{
  "items": [
    {
      "profile_id": 12,
      "profile_name": "Профиль 60×40",
      "product_name": null,
      "code": "P-6040",
      "is_active": true,
      "unit_cost_per_piece": "125.50"
    }
  ]
}
```

| Поле | Тип | Обязательно | Описание |
|------|-----|-------------|----------|
| `items` | array | да | Все профили (пластик), которые пользователь видит в системе |
| `profile_id` | int | да | `PlasticProfile.id` |
| `profile_name` | string | да | Отображаемое имя |
| `product_name` | string \| null | нет | Если есть отдельное «товарное» имя — иначе `null` |
| `code` | string | нет | Код профиля |
| `is_active` | bool | нет | `false` → на фронте пометка «неактивен» |
| `unit_cost_per_piece` | decimal string \| null | да | **Себестоимость 1 шт** (сом), актуальная на сейчас |

**Откуда брать `unit_cost_per_piece` (рекомендация):**

- Последняя рассчитанная себестоимость по профилю (средневзвешенная по партиям / рецепту / FIFO — как у вас в домене), **или**
- Поле на модели профиля, если оно уже есть (`current_unit_cost`, `cost_per_piece` и т.п.)

**Алиасы в JSON (фронт понимает любой из):**  
`unit_cost_per_piece`, `cost_per_piece`, `material_cost_per_piece`, `current_unit_cost`, `unit_cost`.

**Пустой каталог:** `200`, `{ "items": [] }`.

**Ошибки:** не `500` на пустой БД; `403` без прав.

## `GET /api/analytics/summary/` — что изменить в `cards`

Фронт **больше не складывает** `sales_cost_total` в «Всего расходов» и **не показывает** его в строке расходов.

| Поле | Нужно ли |
|------|----------|
| `revenue_total` | да |
| `purchase_total` | да |
| `production_cost_total` | да |
| `sales_cost_total` | опционально (для старых экранов / profit-details), в P&L-карточке не используется |
| `profit_total` | опционально; **маржа на UI** = `revenue_total` − `purchase_total` |

Документ `docs/ANALYTICS_BACKEND.md` устарел в части формулы «расходы = … + sales_cost_total» — обновить на бэке.
