# Спецификация API зарплаты — расширение для неоплативших клиентов

## Текущий эндпоинт GET /api/salary/

Возвращает список расчётов по тренерам за период. Фронтенд ожидает для каждой строки:

### Требуемые поля в ответе (дополнительно к существующим)

| Поле (camelCase) | Тип | Описание |
|------------------|-----|----------|
| `totalClientCount` или `totalClients` | number | (опционально) Всего клиентов. Если нет — фронт считает paidCount + unpaidCount |
| `paidClientCount` или `clientCount` | number | Количество **оплативших** клиентов у тренера за период |
| `unpaidClientCount` | number | Количество **неоплативших** клиентов у тренера за период |

**Альтернативные имена** (фронт поддерживает): `unpaidCount`, `clientsUnpaid`, `unpaid` для неоплативших; `clientsCount`, `clients_count`, `count` для оплативших.

### Пример ответа

```json
{
  "items": [
    {
      "id": 1,
      "trainerId": 5,
      "trainerName": "Иванов Иван",
      "clientCount": 15,
      "unpaidClientCount": 2,
      "income": 30020,
      "trainerPercent": 60,
      "saved": false
    }
  ]
}
```

---

## Логика на фронте

- **Кнопка «Сохранить»** активна только когда:
  1. Месяц уже закончился (прошлый месяц)
  2. `unpaidClientCount === 0` (все клиенты оплатили)
  3. Запись ещё не сохранена (`saved === false`)

- Если `unpaidClientCount > 0` — кнопка неактивна, подсказка: «Сохранить можно только когда все клиенты оплатили».

---

## Рекомендация для бэкенда (опционально)

**POST /api/salary/save/** — при сохранении можно добавить проверку:

- Если у тренера за период есть неоплатившие клиенты → вернуть **400** или **409** с сообщением:
  ```json
  { "error": "Нельзя сохранить: у тренера есть неоплатившие клиенты" }
  ```

Это защитит от обхода проверки через API напрямую.
