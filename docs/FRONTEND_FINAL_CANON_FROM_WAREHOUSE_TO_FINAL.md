# FRONTEND FINAL CANON (Склад -> Final)

## 1. Какие input заменены на select

- `src/features/orders/components/OrdersPage/OrdersPage.jsx`
  - `OrderModal` -> поле `Товар` в строке заявки: `input` заменён на `Select`.
  - Опции берутся из `GET warehouse/batches/` (уникальные `product_name`/`product`).
- `src/features/sales/components/SalesPage/SalesPage.jsx`
  - `SaleModal` (create) -> поле `Товар` в строке продажи: `input` заменён на `Select`.
  - Опции берутся из `GET warehouse/batches/`.
  - При выборе `Партия склада` товар подставляется автоматически из выбранной партии.
- `src/features/returns/components/ReturnsPage/ReturnsPage.jsx`
  - Если выбран `sale_line`, поле `Товар` блокируется и работает как автоподстановка из строки продажи.

## 2. Где detail-first теперь работает

- `Склад` (`WarehousePage`)
  - Клик по строке -> `WarehouseBatchDetailModal`.
  - Редактирования нет, действия выполняются осознанно из карточки/меню.
- `Клиенты` (`ClientsPage`)
  - Клик по строке -> `ClientDetailModal`.
  - Редактирование только отдельной кнопкой.
- `Заявки` (`OrdersPage`)
  - Кнопка номера/пункт `Открыть` -> `OrderDetailModal`.
  - Из detail: редактировать, создать отгрузку, принять оплату, сменить статус, накладная.
- `Продажи` (`SalesPage`)
  - Клик по дате/пункт `Открыть` -> `SaleDetailModal` (добавлено).
  - Из detail: редактировать, документы, смена статуса.
- `Возвраты` (`ReturnsPage`)
  - Клик по номеру/пункт `Открыть` -> `ReturnDetailModal` (добавлено).
  - Из detail: редактировать, накладная.
- `Брак` (`DefectsPage`)
  - Клик по продукту/пункт `Открыть` -> `DefectDetailModal` (добавлено).
  - Из detail: `На переделку` / `Продать как брак` / `Списать` / `Завершить переделку` по статусу.
- `Переделка` (`ReworkRequestsPage`)
  - Клик по номеру/пункт `Открыть` -> `ReworkDetailModal` (добавлено).
  - Из detail: `Начать` / `Завершить` / `Отменить` / `Редактировать`.

## 3. Какие экраны перепакованы в нормальный сценарий

- `Продажи`: список -> detail -> действие.
- `Возвраты`: список -> detail -> действие.
- `Брак`: список -> detail -> выбор следующего шага по статусу.
- `Переделка`: список -> detail -> выбор следующего шага по статусу.
- `Склад`: список -> detail партии + отдельные действия `Резерв`/`Упаковать` с ограничениями по качеству.

## 4. Какие модалки переделаны

- Добавлены detail-модалки:
  - `SaleDetailModal`

  - `DefectDetailModal`
  - `ReworkDetailModal`

## 5. Какие страницы стали понятнее пользователю

- `Склад`
  - резерв для брака запрещён на фронте;
  - упаковка загружает только годные партии;
  - из резерва убран ручной `sale_id`.
- `Продажи`
  - появилось полноценное detail-представление со строками и статусом.
- `Возвраты`
  - продукт не редактируется вручную после выбора строки продажи.
- `Брак / Переделка`
  - ключевые действия теперь идут из карточки записи, а не из набора разрозненных confirm-точек.

## 6. Где фронт всё ещё зависит от backend-контракта

- `Заявки` и `Продажи`: для выбора товара используются данные складских партий (`warehouse/batches/`), т.к. отдельного канонического справочника `product select` endpoint в текущем фронте нет.
- `Возвраты`: лимиты `sale_line` всё ещё зависят от того, какие именно поля ограничения вернёт backend (`returnable_quantity`, `remaining_return_quantity`, `available_for_return`, `max_return_quantity`).
- `Брак/Переделка`: связи (`*_id`/nested object) остаются вариативными в ответах API, фронт продолжает поддерживать обе формы.

## 7. Что осталось

- `Оплаты`: отдельная detail-карточка не добавлялась (сейчас список + edit-modal).
- `Клиенты`: форма клиента всё ещё имеет свободные текстовые поля (`Тип`, `Адрес`, `Комментарий`) — это осознанные текстовые поля, не селекты сущностей.
- `Документы`: для продаж скачивание приведено к каноническому `sales/{id}/nakladnaya/`, но формат файла/имя по-прежнему зависят от заголовков backend ответа.
