  - Поле `Товар` теперь блокируется (`disabled`), если выбрана `Строка продажи`.
  - Товар в этом случае считается подставленным из строки продажи и не редактируется вручную.

## 4) Какие экраны стали пошаговыми

- `Продажи`: список -> detail -> действие (редактирование/документ/статус).
- `Возвраты`: список -> detail -> действие (редактирование/документ).
- `Брак`: список -> detail -> выбор следующего шага (на переделку / продать / списать / удалить).
- `Переделка`: список -> detail -> выбор следующего шага (начать / завершить / отменить / редактировать).

## 5) Какие UX-ошибки были убраны

- Убраны ключевые случаи ручного ввода сущностей, где есть выбор:
  - продукт в заявке/продаже.
- Убран сценарий редактирования как "первое действие" на части экранов:
  - сначала открытие detail.
- На `Складе` введены жёсткие ограничения:
  - резерв брака отключён (`status=available` недостаточно, нужно ещё `quality != defect`).
  - упаковка получает только годные партии (браковые партии фильтруются на клиенте).
- В документах продаж убран UX с локальным `draft.html` при неудаче API:
  - теперь пользователь получает явную ошибку вместо "черновика".

## 6) Где фронт всё ещё зависит от слабого backend-контракта

- `Продажи / накладная`:
  - используется перебор нескольких endpoint (`nakladnaya`, `waybill`, `invoice`) из-за неоднозначного контракта.
- `Возвраты`:
  - лимиты возврата по строке читаются по нескольким альтернативным ключам (`returnable_quantity`, `remaining_return_quantity`, `available_for_return`, `max_return_quantity`).
- `Брак/Переделка`:
  - фронт учитывает вариативные структуры ссылок (`*_id`, nested object, number/string id).

## 7) Что ещё осталось (реально)

- `Оплаты` пока остаются без отдельной detail-карточки (есть список + edit modal).
- В ряде форм остаются числовые `input` для сумм/количества; это бизнес-ввод, а не выбор сущности.
- `Аналитика` не подключена к realtime-refetch, обновляется по фильтрам/перезагрузке.
- Для полной системной унификации нужно ещё привести стили detail-карточек и action-панелей к единому shared-компоненту (сейчас логика унифицирована, визуальная система частично разная по модулям).
