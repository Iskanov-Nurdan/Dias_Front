# Производство: профиль → заготовка → отдельные строки в ОТК

## Задача

Одна клиентская заявка может содержать **несколько профилей** (`order_lines`). Оператор на **Производство → Заявки** для **каждого профиля** выбирает **свою заготовку**. После «Старт» в **ОТК** должна быть **отдельная строка на каждый профиль** (отдельный `BlankProductionRun`), с понятной парой **Товар + Заготовка**.

Фронт уже шлёт привязку по позициям. Нужна поддержка на бэке.

---

## GET `/api/production/requests/`

В каждой позиции `order_lines[]` желательно:

```json
{
  "id": 101,
  "profile_id": 5,
  "profile_name": "Пластиковый профиль 5м",
  "quantity": "20",
  "allowed_blank_ids": [1, 3]
}
```

- `allowed_blank_ids` на **позиции** — заготовки, подходящие к **этому** профилю + универсальные (`plastic_profile=null`).
- На заявке в целом — `allowed_blank_ids` как fallback, если на позиции пусто.

---

## POST `/api/production/requests/{order_id}/start/`

### Одна позиция (legacy + явная позиция)

```json
{ "blank": 1, "order_line_id": 101 }
```

или только `{ "blank": 1 }`, если в заявке одна строка.

### Несколько позиций — **основной формат**

```json
{
  "line_starts": [
    { "order_line_id": 101, "blank": 1 },
    { "order_line_id": 102, "blank": 2 }
  ]
}
```

Если `order_line_id` ещё нет в БД — допустим fallback (на время миграции):

```json
{ "profile_id": 12, "blank": 2 }
```

**Не использовать** для этого сценария общий `{ "blanks": [1, 2] }` без привязки к профилю — в ОТК непонятно, какой товар с какой заготовкой.

### Поведение бэка

1. Валидировать: каждая позиция заявки ровно один раз в `line_starts`, у каждой — `blank`, заготовка разрешена для `profile_id` этой строки.
2. На **каждый** элемент `line_starts` создать **отдельный** `BlankProductionRun` (и связанную логику списания кг с цеха):
   - `product_id` / `product_name` — из **профиля этой строки**
   - `blank_id` / `blank_name` — из выбранной заготовки
   - связь с `order_line_id` и `client_request_id` (заявкой)
3. **Не** склеивать несколько профилей в одну запись ОТК.
4. Смена: **без линии** — достаточно личной смены (`shifts/my/`, `line=null`) или без проверки линии; тексты ошибок без «на линии».

### Коды ошибок

- `LINE_STARTS_REQUIRED` — пустой `line_starts` при нескольких `order_lines`
- `MISSING_LINE_BLANK` — не все позиции покрыты
- `UNKNOWN_ORDER_LINE` — чужой `order_line_id`
- `BLANK_PROFILE_MISMATCH` — заготовка не для этого профиля
- `DUPLICATE_BLANKS` / `BLANK_NOT_FOUND` / `BLANK_INSUFFICIENT_STOCK` — как сейчас

## GET `/api/workshop/blank-production-runs/` (ОТК)

Каждая запись — **один** run = один профиль + одна заготовка:

```json
{
  "id": 55,
  "product_id": 5,
  "product_name": "Пластиковый профиль 5м",
  "blank_id": 1,
  "blank_name": "Заготовка ПВХ смесь №1",
  "order_line_id": 101,
  "client_request_id": 42
}
```

Фронт ОТК уже выводит колонки **Товар** и **Заготовка** — важно, чтобы `product_name` и `blank_name` соответствовали **паре с производства**, а не первой строке заявки.

---

## Проверка

1. Заявка: профиль 5м + профиль 6м → на производстве две строки, у каждой свой селект заготовки.
2. Старт с двумя разными заготовками → в ОТК **две** строки с правильными парами товар/заготовка.
3. Брак и склад ГП обрабатываются **по каждой** строке ОТК отдельно.

Тесты: расширить `apps/production/tests/test_production_requests_api.py` (line_starts → 2 runs в OТК).
