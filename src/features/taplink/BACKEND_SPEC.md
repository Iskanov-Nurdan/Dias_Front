# Taplink — Спецификация для бэкенда

> Бэкенд уже подключён (`TAPLINK_BACKEND_ENABLED = true` в `shared/api/client.js`) — `GET/PUT /api/taplink/` и загрузка файлов работают. Этот файл фиксирует полный контракт и то, что нужно проверить/доделать:
> 1. **Лимит видео увеличен с 3 до 5** — если где-то на бэкенде есть валидация длины массива `videos` (≤3), её нужно поднять до 5. Если валидации длины нет — ничего менять не нужно, массив и так гибкий JSON.
> 2. **Раздача видео-файлов** должна поддерживать `Range`/`206 Partial Content` и корректный `Content-Type` — без этого `<video>` на сайте может не проиграть файл (см. раздел «Важно про раздачу видео-файлов» ниже).
> 3. **Эндпоинт записи на тренировку** (`POST /api/taplink/booking/`) — уточнить, что заявка создаёт лид с `channel: "taplink"`, видимый в CRM → «Заявки» → вкладка «Таплинк».

---

## Авторизация

Все `PUT` / `POST` / `DELETE` запросы требуют заголовок:
```
Authorization: Bearer <access_token>
```
Токен тот же, что используется во всём приложении (`localStorage.getItem('token')`).

`GET /api/taplink/` — **публичный**, без авторизации (страница открыта для всех).

### 2. Сохранить конфиг страницы
```
PUT /api/taplink/
Content-Type: application/json
Authorization: Bearer <token>
```
- Тело: **тот же формат**, что и ответ `GET /api/taplink/`
- Поля `photo`, `bg`, `videos[*]` содержат **URL** файлов (строки вида `"/media/taplink/abc.jpg"` или пустую строку `""` / `null`)
- Ответ `200 OK`: сохранённый объект (тот же формат)
- Ответ `400 Bad Request`:
```json
{ "error": { "message": "Описание ошибки" } }
```

---

### 3. Загрузить файл (фото или видео)
```
POST /api/taplink/upload/
Content-Type: multipart/form-data
Authorization: Bearer <token>
```
Поля формы:
| Поле      | Тип    | Описание                                                                                      |
|-----------|--------|-----------------------------------------------------------------------------------------------|
| `file`    | File   | Загружаемый файл                                                                              |
| `context` | string | Подсказка для организации файлов: `hero-bg`, `sport-photo`, `trainer-photo`, `sport-video`, `trainer-video` |

Ответ `201 Created`:
```json
{
  "url": "https://rahmanata.kg/media/taplink/uploads/abc123.jpg"
}
```
Ошибки:
```json
{ "error": { "message": "Файл слишком большой. Максимум 20 МБ." } }
```

Ограничения:
- **Изображения**: JPEG, PNG, WEBP — до **5 МБ**
- **Видео**: MP4, WEBM — до **200 МБ**
- Хранить в папке `media/taplink/` (или CDN)
- URL должен быть абсолютным (начинаться с `https://`) или корневым (`/media/...`)

**Важно про раздачу видео-файлов** (фронтенд рендерит их через нативный `<video>`, не через плеер):
- Корректный `Content-Type` (`video/mp4`, `video/webm`) в ответе на GET файла.
- Обязательна поддержка `Range`-запросов (ответ `206 Partial Content` с заголовком `Content-Range`) — без этого `<video>` не сможет перематывать и может не проиграть файл вовсе в некоторых браузерах.
- CORS-заголовки на раздачу медиа (`Access-Control-Allow-Origin`) — фронтенд может обращаться к файлам с другого origin (например, при локальной разработке).

---

### 4. Удалить файл
```
DELETE /api/taplink/upload/
Content-Type: application/json
Authorization: Bearer <token>
```
Тело:
```json
{ "url": "https://rahmanata.kg/media/taplink/uploads/abc123.jpg" }
```
Ответ `204 No Content` или `200 OK`.

### 5. Записаться на тренировку (booking)
```
POST /api/taplink/booking/
Content-Type: application/json
```
- Авторизация: **не требуется** (публичная форма записи на странице)
- Тело запроса:
```json
{
  "name": "Иван Иванов",
  "phone": "+996700123456",
  "sport": "Бокс",
  "trainer": "Азизбек уулу Баяман",
  "preferredTime": "Вечером после 18:00",
  "comment": "Первое занятие бесплатно?"
}
```

| Поле            | Тип    | Обязательно | Описание                                  |
|------------------|--------|-------------|--------------------------------------------|
| `name`           | string | да          | ФИО клиента                                |
| `phone`          | string | да          | Телефон, фронтенд гарантирует ≥12 цифр (код страны + номер) |
| `sport`          | string | да          | Название секции (совпадает с `sports[].name`) |
| `trainer`        | string | нет         | ФИО тренера, если выбран конкретный        |
| `preferredTime`  | string | нет         | Удобное время (свободный текст)            |
| `comment`        | string | нет         | Комментарий клиента                        |

- Ответ `201 Created`: `{ "id": 123 }` (или сам созданный объект)
- Ответ `400 Bad Request`: единый формат ошибок (см. ниже), например если `phone` не проходит валидацию на бэкенде

**Обязательно: заявка должна создавать запись в общей таблице лидов** (тех же, что видны в разделе «Заявки» → вкладка «Таплинк» в CRM), с полем `channel: "taplink"`, чтобы отдел продаж видел её в `TaplinkLeadsTab`. Ожидаемые поля лида:

| Поле                        | Тип     | Описание                                          |
|-----------------------------|---------|----------------------------------------------------|
| `name`, `phone`             | string  | из формы                                           |
| `taplinkSport` / `taplink_sport`     | string | из формы (`sport`)                          |
| `taplinkTrainer` / `taplink_trainer` | string | из формы (`trainer`)                        |
| `status`                    | enum    | `pending` \| `accepted` \| `rejected` \| `spam` — новая заявка создаётся со статусом `pending` |
| `isDuplicate` / `is_duplicate` | boolean | `true`, если уже есть заявка с этим же телефоном за последние N дней (дедупликация) |
| `createdAt`                 | ISO datetime | момент создания                              |

Телефон стоит нормализовать и проверять по тому же формату, что уже используется в CRM: `^\+996\d{9}$|^0\d{9}$`.

## Хранение в БД

Рекомендуется хранить весь конфиг как **один JSON-документ** в одной строке таблицы `taplink_config`:

```sql
CREATE TABLE taplink_config (
  id         SERIAL PRIMARY KEY,
  data       JSONB NOT NULL,
  updated_at TIMESTAMPTZ DEFAULT NOW(),
  updated_by INTEGER REFERENCES users(id)
);
```

При `GET` — возвращать `data` последней строки.  
При `PUT` — вставлять новую строку (история изменений) или обновлять существующую.

---

## Формат ошибок (единый для всех эндпоинтов)

```json
{
  "error": {
    "message": "Человекочитаемый текст ошибки"
  }
}
```
HTTP коды: `400`, `401`, `403`, `413` (файл слишком большой), `500`.

---

## Примечания по видео

Видео-файлы загружаются через тот же `POST /api/taplink/upload/` (поле `context`: `"sport-video"` / `"trainer-video"`).  
В поле `videos[i]` хранится URL видео на сервере.

> В текущей версии фронтенда видео из editor сохраняются как `blob:` URL только на время сессии.  
> После подключения бэкенда — видео сразу загружаются на сервер через этот же эндпоинт.
