# Taplink Booking — Спецификация для бэкенда

> Фронтенд готов. Форма записи отправляет заявки на `POST /api/taplink/booking/`.
> Бэкенд создаёт объект Lead и возвращает подтверждение.

---

## Эндпоинт

```
POST /api/taplink/booking/
Content-Type: application/json
```
**Авторизация: не требуется** (публичный эндпоинт, посетитель сайта)

### Тело запроса

| Поле            | Тип    | Обязательно | Описание                                              |
|-----------------|--------|-------------|-------------------------------------------------------|
| `name`          | string | да          | ФИО клиента                                           |
| `phone`         | string | да          | Телефон в кыргызском формате (+996 XXX XXX XXX)       |
| `sport`         | string | да          | Название секции (напр. "ММА", "Бокс")                 |
| `trainer`       | string | нет         | Имя тренера (строка, не FK)                           |
| `preferredTime` | string | нет         | Удобное время (напр. "Пн, Ср 18:00–20:00")            |
| `comment`       | string | нет         | Комментарий клиента                                   |

### Пример запроса

```json
{
  "name": "Бекматов Асан",
  "phone": "+996 555 123 456",
  "sport": "ММА",
  "trainer": "Алибек Жаксыбеков",
  "preferredTime": "Вечером, Пн-Пт после 18:00",
  "comment": "Без опыта, хочу попробовать"
}
```

### Ответ `201 Created`

```json
{
  "id": 42,
  "message": "Заявка принята. Мы свяжемся с вами в течение часа."
}
```

### Ответ `400 Bad Request`

```json
{ "error": { "message": "Описание ошибки" } }
```

### Ответ `429 Too Many Requests` (rate limit)

```json
{ "error": { "message": "Слишком много заявок. Попробуйте позже." } }
```

---

## Что делает бэкенд при получении запроса

1. **Валидирует** — name и phone обязательны, остальные опциональны
2. **Спам-защита** — rate limiting по IP: не более 3 заявок в час с одного IP
3. **Дублирование** — проверить, не было ли заявки с таким же phone за последние 24ч
   - Если был — вернуть `201` (клиент не должен знать), но внутри пометить `is_duplicate: true`
4. **Создать Lead** со следующими полями:

```
name          = body.name
phone         = body.phone
channel       = 'taplink'          ← фиксированное значение, идентифицирует источник
sport         = body.sport         ← текстовое поле (не FK)
trainer       = body.trainer       ← текстовое поле (не FK)
preferredTime = body.preferredTime ← текстовое поле
comment       = body.comment
status        = 'pending'          ← новая заявка
source_ip     = IP адрес запроса   ← для антиспама
created_at    = now()
```

## Изменения в модели Lead

Добавить поля к существующей таблице `leads`:

| Новое поле      | Тип          | Default | Описание                                     |
|-----------------|--------------|---------|----------------------------------------------|
| `sport`         | VARCHAR(100) | null    | Название секции из таплинка (текст)          |
| `trainer`       | VARCHAR(200) | null    | Имя тренера из таплинка (текст)              |
| `preferred_time`| VARCHAR(200) | null    | Удобное время занятий (текст)                |
| `is_duplicate`  | BOOLEAN      | false   | Дублирующаяся заявка (скрытый флаг)          |
| `source_ip`     | INET         | null    | IP адрес клиента                             |

> Поле `status` уже существует. Добавить значение `'spam'` и `'pending'` в допустимые значения:
> `'pending'` (по умолчанию) | `'accepted'` | `'rejected'` | `'spam'`

## Антиспам на бэкенде

1. **Rate limit по IP**: max 3 заявки за 1 час → `429`
2. **Дублирование по телефону**: тот же phone за последние 24ч → пометить `is_duplicate=true`, вернуть `201` (не показывать ошибку клиенту)
3. **Базовая валидация телефона**: должен содержать минимум 10 цифр
4. **Базовая валидация имени**: минимум 2 символа

## НОВОЕ: публичный график тренера для формы записи

**Проблема:** поле «Удобное время занятий» в форме записи раньше показывало вручную вписанный в редакторе текст (мог не совпадать с реальным графиком тренера). Теперь фронт умеет тянуть настоящий график — нужен публичный эндпоинт.

### GET /api/taplink/trainers/{id}/schedule/

**Авторизация: не требуется** (публичная страница записи, посетитель не залогинен).

`{id}` — id тренера из основной CRM-таблицы `trainers` (тот же id, что используется в `GET /api/trainers/{id}/schedule/` для админки).

**Ответ** — тот же формат, что и у существующего авторизованного `GET /api/trainers/{id}/schedule/` (просто без проверки Authorization):

```json
{
  "weekdays": [
    { "weekday": 1, "enabled": true, "intervals": [{ "start": "10:00", "end": "11:30" }] }
  ]
}
```

Проще всего реализовать как публичную обёртку над тем же view/сериализатором, что и приватный эндпоинт, только без `permission_classes` (или с `AllowAny`), плюс:
- Если тренер скрыт/уволен/не существует — `404`.
- Отдавать **только** сам график (weekday/intervals). Никаких персональных/финансовых данных тренера через этот эндпоинт быть не должно — он публичный.

> Фронтенд дополнительно показывает менеджеру визуальный маркер ⚠ для подозрительных заявок:
> - Телефон не в формате +996XXXXXXXXX или 0XXXXXXXXX
> - Имя короче 3 символов

## Статусы заявок — что делает менеджер в CRM

| Статус     | Значение                                 | Действие в CRM               |
|------------|------------------------------------------|------------------------------|
| `pending`  | Новая заявка, ещё не обработана          | Нажимает «Запишется» или «Отказался» |
| `accepted` | Клиент решил заниматься                  | Звонок совершён, договорились |
| `rejected` | Клиент не захотел заниматься             | Отказался после контакта      |
| `spam`     | Фейковая / ботовая заявка                | Помечает вручную              |
